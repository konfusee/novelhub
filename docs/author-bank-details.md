# Author payout bank details

The earnings page includes a bank form at `/author/earnings#payout-bank`. Owner-only GET/PUT `/author/bank-details` use private/no-store responses. PUT accepts exactly the three bank fields and the displayed account version, trims text, rejects blank/control-character inputs and preserves leading zeros in account numbers.

The Author endpoint requires the active Author role. Saving rechecks active account status, Author history and credentials, serializes with account suspension/deletion and monthly evaluation, and appends an audit digest in the same transaction. Stale versions return 409; an audit failure rolls the entire update back. Private bank fields stay excluded from normal account serialization.

The saved bank is used for future evaluations. Existing withdrawal/payout bank snapshots are not rewritten. There is no manual withdrawal request or automatic transfer. Financial notifications now link to `/reader/author-payouts`, with `#payout-bank` for missing bank details. Notification URLs are generated by the server and never copied from payload links; transient email addresses remain private.

## Financial access after Author role removal

`/reader/author-payouts` reuses the bank form, payout history and detail UI in the Reader layout. `/reader/author-finance/bank-details` and `/reader/author-finance/payouts` require an authenticated account with `everAuthor=true`, including former Authors. Active account status and credential/authorization epochs are checked again inside bank updates. Each query is scoped to the authenticated account; request input cannot select another owner.

Ordinary Readers, Admins and Moderators without Author history cannot use these endpoints. Authoring routes keep their existing active-role guard. Suspended accounts cannot log in; Admins can still settle their already pending payouts through the existing reconciliation flow. No manual withdrawal or Author workspace permission is granted by this retained financial access.

Validation covers access control, stale writes, rollback, private serialization, bank snapshot immutability, financial notification links, form save/error/reload behavior and the existing earnings page. No backend schema changes; media/AI remain deferred. Browser visual acceptance remains separate.
