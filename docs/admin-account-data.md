# Live Admin account directory

`GET /api/admin/accounts` requires Admin authorization and returns actual MongoDB accounts, current active staff assignments, story counts and the account's Reader-coin balance. Server-side filters cover literal display-name/email search or exact ObjectId, exclusive primary role, account status, stable pagination and newest/oldest/story-count/Reader-balance sorting. Page size is bounded to 50 and query length to 100. Summary totals remain global while the list total follows the filters. Reader in this directory means an account without an active staff assignment; staff retain Reader capabilities elsewhere.

The aggregation uses allowlisted DTO fields. Anonymized accounts expose no email or active staff labels, including inconsistent legacy records. A missing Reader wallet is `null`, not an invented zero. Author earnings do not become Reader coins. Authentication, bank details, retained payout contacts and private snapshots are never returned.

`GET /api/admin/accounts/:accountId` provides allowlisted identity fields, actual wallet balances separated by purpose, the five most recently updated owned stories, and ten recent audit events directly targeting the account. This is a bounded account summary, not an exhaustive cross-aggregate audit history. Missing records return 404; no default/sample user is substituted. Both endpoints use private/no-store caching.

The existing `/admin/users` shell, filter/table layout, row inspection, selected-row treatment, responsive table overflow and information cards are retained. The directory and inspector no longer import domain mock data or use simulated latency. Search/filter/pagination request the server and cancel superseded reads. Real Author revocation refreshes the main directory and counts as well as the dedicated Author card. Unsupported invitation, CSV export, generic role editing, coin adjustment, warning and suspension actions are disabled with an explanation rather than reporting simulated success. The existing Author application and revocation flows remain operational. The mock revenue-agreement page is no longer offered as a financial action from actual account details; migrating that page remains separate work.

No backend model/schema or shared UI primitive was changed. No accounts, money or transactions were created in the shared database. Browser proof uses disposable MongoDB fixtures: 13 accounts, a real story, 13 Reader coins and 9,999 Author earnings. It verifies pagination, search, actual inspector data, light/dark mobile (390px), tablet (768px), laptop (1024px) and desktop (1536px). Document width did not overflow; wide tables retain their own horizontal scroller. The browser error console was empty, and the helper/database were stopped after verification.

Tests: `backend/test/admin-users.test.js` covers Admin access, strict filters, aggregate totals, literal search, distinct pages, sorting, wallet separation, actual story/audit detail and anonymized/private-field redaction. Frontend tests cover live values, server requests, actual inspector content, errors without mock fallback, disabled unsupported actions and directory-refresh notification after Author revocation. Other Admin pages and remaining domain mock datasets are outside this increment.

Validation for this increment: 6 backend and 14 related frontend tests passed; lint, targeted formatting, Vietnamese content validation (1,489 keys), icon checks and production build passed. Main API/frontend readiness endpoints returned HTTP 200 after disposable test cleanup.

Follow-up: the account-specific agreement page now reads real current rates and bounded history through the Admin agreement API; active Authors have an inspector link again. See `author-revenue-agreement.md`. Agreement editing remains unsupported and the page no longer offers simulated localStorage saves.
