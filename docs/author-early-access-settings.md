# Draft chapter early-access settings

Authors can open “Thiết lập đọc sớm” from eligible chapter rows in the story manager. The existing shell, table, shared Modal/Input/Button components and semantic colors remain. The manager shows a saved draft price/duration separately from its unreleased status; no paid publication is implied.

`GET` and `PUT /api/author/stories/:storyId/chapters/:chapterId/early-access` require the current Author account and ownership. Read responses are private/no-store. Only an editable chapter revision belonging to that exact story/chapter/Author is eligible. Submitted, approved, scheduled, published, archived, cancelled or previously released chapters cannot be configured; frozen/reviewing/archived stories are also blocked. Original first-release dates and early-access end dates are never reset by this command.

Enabling requires safe integer price/duration values within an actual, effective MongoDB PolicyVersion. There is no invented frontend policy or silent policy fallback. Default product policy values are 200–5,000 coins and 1–14 days when an Admin has installed that policy. Future or draft policy records are not selected. The request carries chapter/story versions and the exact policy ID/version. The transaction locks the Author account, checks current authorization, pins the policy version, updates chapter settings and increments the story version, then appends the required audit event with before/after settings, policy facts and a digest. Failure rolls back all writes. Stale or duplicate concurrent writes cannot overwrite newer settings. Disabling clears draft settings and remains possible without an effective policy.

This is preparation for early access, not the paid-release/unlock/settlement workflow. It never sets endsAt, firstReleasedAt, publishedRevisionId, a public status or any financial record. The existing release guard continues to reject enabled early-access chapters; the form states that the present publication flow is free-only and the setting must be disabled before using that flow. First paid publication, immutable release-time terms, entitlement purchases, settlement and automatic expiry integration still remain. No backend models/schemas changed.

The form loads fresh settings/policy, validates integers and bounds, avoids duplicate pending requests and requires a reload after failed or uncertain writes. It only closes as successful after a matching chapter/settings/version response. Missing policy, locked chapter, load errors and write errors have explicit states. Frontend tests remain under frontend/test.
