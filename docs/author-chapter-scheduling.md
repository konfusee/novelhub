# Approved free chapter scheduling

`PUT /api/author/stories/:storyId/chapters/:chapterId/schedule` requires the owning active Author and accepts only `revisionId`, `submissionId`, `expectedVersion`, `expectedStoryVersion`, and `requestedReleaseAt`. The time must be an ISO datetime with an explicit UTC offset; `null` cancels a schedule. Fresh chapter and story versions are required for scheduling, rescheduling and cancellation. An elapsed time becomes `due`; a future time becomes `scheduled`. Cancellation restores `approved` without publishing. Even an invalidated immutable package can have its schedule cancelled when its source identities still match.

Only approved, immutable free chapter packages with valid rights, terminal evidence, supported content and unchanged illustrated bytes can be scheduled. A parent or earlier chapter may still block release. Published, unpublished, archived, cancelled, draft and frozen targets cannot be scheduled through this operation. No financial or access policy is changed.

The API server starts a sweep on boot and every 30 seconds. MongoDB chapter state is the durable queue; no in-memory timer represents an individual chapter. A restart picks up elapsed schedules. Each process runs one sweep at a time and waits for its current sweep before disconnecting MongoDB on shutdown.

The sweep processes chapters by story and chapter order. Actual publication reuses the immediate publication transaction, including active Author authorization, parent visibility and approved snapshot, first-release ordering, immutable package digests, terminal evidence, current rights and image-byte/version pins. Concurrent sweeps cannot publish a chapter twice. Chapters without an explicit requested time never enter this queue. A previously released and subsequently unpublished preceding chapter does not block later first releases.

Blocked chapters become `due`, retain private content and record a system deferral with the failed checks. Repeated identical failures do not create duplicate audit records. Future sweeps retry automatically. An unexpected failure for one chapter is logged, its publication transaction rolls back, and it is deferred without stopping unrelated chapters. Failure to persist that deferral still fails the sweep and is logged by the runner. Publication and schedule audit failures roll back their associated domain writes.

The manager now opens schedule controls from a server-provided `canManageSchedule` hint. Scheduled/due chapters open “Đổi hoặc hủy lịch”; their separate content link accurately says “Xem nội dung”. The dialog loads `GET .../schedule`, displays actual immutable-package checks, explains parent/order waiting, and converts the device-local datetime into an explicit UTC ISO timestamp. An elapsed time is explained before saving. Saving and cancellation refresh the manager from MongoDB. Invalid responses do not report success, and a 409 disables further writes until the Author explicitly reloads the checks. An invalidated scheduled package still exposes its original source identities for cancellation without allowing rescheduling.

This increment changes no backend schemas/models or existing shared UI primitives. The broad AUT-03/AUT-10 use cases remain partial. Remaining scheduling work: requested release time at initial submission and the corresponding human approval transition; complete role-removal/account-deletion cancellation hooks; operational scheduling visibility. Early-access publication remains separate work and cannot use this free-chapter endpoint.
