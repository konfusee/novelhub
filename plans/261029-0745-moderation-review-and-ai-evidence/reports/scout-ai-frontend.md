## Summary
- All five AI evidence models already exist and are exported (`backend/src/models/index.js:42-48`). Idempotency anchors: `ProcessingAttempt.attemptKey` unique, `EmbeddingArtifact` unique on (revisionId, model, chunkingVersion, passageId), `LlmReview` one succeeded per batch (partial unique). `EvidenceBatch` has NO unique index per revision and NO status guard; only `activeLeaseId` + optimistic `version`.
- Plain text for a chapter revision = `chapterTextProjection(revision)` (string[]; handles blocks-v1/v2/v3). Story revision text = `content.title` + `content.description` (`story-v1`). No similarity-source projection helper exists; published/pending eligibility must be assembled from Chapter + PublicationSubmission + Story (section 3).
- Submission creates batch {stage:embedding,status:pending} (`modules/author-submissions.js:351-362`); submission status starts `validated` and NOTHING in src moves it to `pending-review` (`pending-review` appears only in consumers: `admin-dashboard.js:54`, `workspace-data.routes.js:233`, cancel paths). Claim fields exist on PublicationSubmission but no code sets them (cancel paths only clear them).
- `config/env.js` = zod object plus imperative all-or-none checks after parse; `backend/test/config.js:5` builds test env by parsing `.env.example`, so new OPENAI_* vars MUST be valid/blank-safe there.
- Frontend moderator pages are fully mock (`useMockResource` + `data/mock/moderation.js` + inline constants), hard-coded strings, no `useLocale`. Locale blocks `manualReview`, `reviewHistory`, `reviewClaims` exist in `vi.json` but are unreferenced in `src`/`test`.

## 1. AI evidence models (backend/src/models/review/)
Shared helpers: `mutableOptions` = timestamps, versionKey `version`, optimisticConcurrency, strict:throw (`models/shared/schema.js:11-17`); `appendOnlyOptions` = createdAt only, no versionKey (`schema.js:20-24`); `appendOnly` plugin rejects update/delete/replace/non-insert bulkWrite and re-save (`schema.js:44-64`). `lockFields` modes insert-only/set-once/frozen-by (`models/shared/guards.js:31-39`); `forwardOnly` (`guards.js:124`) checks transitions on doc save (reads stored state, `:163-166`) and query updates (`:140`). Writes through `Model.collection` bypass guards and are forbidden (`guards.js:1-3`).

### EvidenceBatch (`evidence-batch.model.js`, collection evidenceBatches)
- Stages `embedding|comparison|llm` (:2); statuses `pending, embedding-complete, discovery-complete, llm-complete, available-for-human-review, failed` (:3-10).
- Fields (:13-20): submissionId*, revisionId*, packageDigest, stage, status (default pending), failedStage, outputSchemaVersion, activeLeaseId. mutableOptions. No `forwardOnly`/`lockFields`: status transitions and immutability of submissionId/revisionId/packageDigest are NOT model-enforced.
- Indexes (:24-25): {submissionId:1,createdAt:-1}; {revisionId:1,status:1}. Neither unique.
- Terminal-ready used by gates: `available-for-human-review` AND stage `llm`, or `failed` with failedStage in the three stages (`modules/review-evidence.js:3-8`). Gates also require batch.submissionId/revisionId/packageDigest to match the submission (`author-story-release.js:53-59`, `author-chapter-release.js:115-121`). A pending batch with no lease is accepted if ModerationHistory has `manual-review.decided`/`approved` with correlationId `manual-review-ai-deferred-v1` matching evidenceBatchId+version+beforeStateDigest (`review-evidence.js:10-24`): legacy AI-deferred path.

### ProcessingAttempt (`processing-attempt.model.js`)
- Stages same three (:3); statuses `claimed, started, succeeded, failed, stale` (:4).
- Fields (:7-20+): batchId*, revisionId*, stage*, attemptKey*, leaseId, claimVersion, leaseExpiresAt, provider, status*, requestFingerprint, responseMetadata(Mixed), failureCode, startedAt, finishedAt, retryOf (ref ProcessingAttempt), staleAt.
- Guards: `lockFields` insert-only on batchId, revisionId, stage, attemptKey, leaseId, claimVersion (:26-28); `forwardOnly` status claimed->[started,stale], started->[succeeded,failed,stale], succeeded/failed/stale terminal (:29+).
- Indexes: UNIQUE {attemptKey:1}; {batchId:1,stage:1,createdAt:-1}. A deterministic attemptKey is the idempotent claim primitive (duplicate insert throws E11000). Lease itself is NOT unique-indexed; because leaseId/claimVersion are insert-only, a lease steal/renewal must create a NEW attempt (use `retryOf`, mark old `stale`) or only mutate leaseExpiresAt/status. CAS on the doc uses `version` (optimistic concurrency).

### EmbeddingArtifact (`embedding-artifact.model.js`) append-only
- Fields (:4-14+): revisionId*, batchId*, model*, dimensions* (min 1), passageId*, passageOrder, offsets(Mixed), textReference, textHash, authorAccountId, eligibilityStatus, vector* ([Number]; validator length === dimensions, :15-24), provider, status, chunkingVersion*.
- Indexes: UNIQUE {revisionId, model, chunkingVersion, passageId}; {batchId, passageOrder}. The same revision/model/chunking cannot be embedded twice even from another batch (retry must reuse or skip existing artifacts). No update allowed.
- No storyId/chapterId/source-kind fields; `authorAccountId` and `eligibilityStatus` are the only denormalized pre-filter hooks. `status` is a free String.

### SimilarityFinding (`similarity-finding.model.js`) append-only
- Fields (:4-15): batchId*, revisionId*, sourceChapterId* (ref Chapter), sourceRevisionId*, sourceAuthorAccountId*, queryPassageId*, sourcePassageId*, rank* (int>=1), score* (0..1), matchedSnippets[Mixed], evidenceHash, occurredAt.
- Indexes: {batchId:1,score:-1}; {revisionId:1,sourceRevisionId:1}. No unique key: finding-write idempotency must come from the comparison attempt or a new unique like {batchId,queryPassageId,rank}. `sourceChapterId` is REQUIRED, so findings only point at chapters.
- score max 1: confirm the raw cosine score from `$vectorSearch` lies in 0..1 [INFERENCE, unverified].

### LlmReview (`llm-review.model.js`) mutable
- Statuses `pending, succeeded, failed` (:2). Fields (:5-16): batchId*, revisionId*, status*, criteriaVersion, inputFingerprint, suggestions[String], riskReasons[String], evidenceRefs[Mixed], provider, providerResponseRef (select:false), completedAt, failureCode.
- Index (:20): UNIQUE {batchId:1} with partialFilterExpression status:succeeded (many failed/pending allowed, one succeeded). No `forwardOnly` on status. No structured fields for rights assessment, per-criterion result or model name/usage.

### PublicationSubmission and ModerationHistory (decision context)
- `publication-submission.model.js`: statuses `validated, pending-review, decision-pending, approved, rejected, cancelled` (:2-9); cancellationReason `author-role-removed|account-deleted` (:10); fields storyId, chapterId?, revisionId*, authorAccountId*, status, submittedAt, currentEvidenceBatchId, packageDigest, decisionSummary, claimOwnerAccountId, claimExpiresAt, claimVersion, claimReleaseHistory, cancelledAt (:13-27). Indexes: UNIQUE {revisionId:1} (one submission per revision: resubmission = new revision) and {status,claimExpiresAt,submittedAt} (:29-30).
- `moderation-history.model.js` append-only (:1-27): aggregateType, aggregateId, action, outcome, submissionId, revisionId, evidenceBatchId, evidenceBatchVersion, actorAccountId*, actorAuthorizationEpoch, reason, feedback, beforeStateDigest, afterStateDigest, occurredAt, correlationId. Author UI reads `action, outcome, feedback, occurredAt` (`author-submissions.js:436-441,481-488`) and `decisionSummary` (`:466`); `processing` = {status, failedStage} from the batch (`:477`).

## 2. Content shape for embedding, rights, package digest
- ContentRevision (`models/content/content-revision.model.js`): contentType story|chapter (:15), content Mixed (:27), formatVersion (:28), validation Mixed (:29), rightsDeclarationId (:31), status enum (:3-12), packageDigest/rightsDigest/mediaDigest (:35-37), mediaIds (:38); frozen-by `immutableAt` lock (:42-62); unique {contentType,storyId,chapterId,revisionNumber} (:64).
- story-v1 content: strict `{title (1-200), description (1-10000), categoryIds[]}` (`author-submissions.js:28-34`; re-validated at `author-submitted-package.js:77-88`). Text = title + description (submit flow uses `content.description`, `author-submissions.js:80-82`).
- blocks-v1 chapter: `{title, blocks:[{type:paragraph,text}]}` (`modules/chapter-document.js:11-19`, `supportsTextEditor` :21-26).
- blocks-v2: `richChapterDocument` = {title, blocks: paragraph|heading(level 2|3)|quote with inlines[{text,marks}], scene-break} (`rich-chapter-document.js:5-61`). blocks-v3 = v2 plus `image` blocks (mediaId, alt, caption; max 20) (`:62-68`); chosen by `chapterDocumentFormat` (`:74-75`).
- PLAIN TEXT FUNCTION: `chapterTextProjection(revision)` (`rich-chapter-document.js:120-134`) returns string[] (one per paragraph/heading/quote; skips scene-break and image; v1 uses block `text`; unparsable v2/v3 returns []). Already used by `author-submissions.js:78,81,202`, `author-dashboard.js:137`, `author-drafts.js:32`. It excludes chapter title and image alt/caption. `readRichChapter(revision)` (`:77-118`) normalizes every format to {title, blocks} (v1 paragraphs become inlines) and throws 409 `unsupported_editor_format` on invalid data: used for the reading view.
- Rights: `RightsDeclaration` (`models/content/rights-declaration.model.js`): storyId, submissionId, revisionId, basis (`original|licensed`, :3), asserted, sourceLicenceNote, declaredBy, declaredAt, status draft|asserted|superseded, immutableAt (:5-20); frozen-by immutableAt (:24-37); status forwardOnly (:38-42); UNIQUE {storyId,revisionId} (:43). `rightsFacts(rights)` = {basis, asserted, sourceLicenceNote||""} (`submission-digests.js:19-23`). Non-illustrated chapters reuse the parent story-revision rights; illustrated (blocks-v3) chapters and story revisions get their own rights doc (`author-submissions.js:126-135,178-190`, `author-submitted-package.js:67-73`).
- Package digest (`author-submissions.js:~300-325`): `digest({formatVersion, content, rightsDigest, mediaDigest})`; `digest` = sha256 hex of JSON.stringify of key-sorted canonical value (`submission-digests.js:2-17`); rightsDigest = `digest(rightsFacts(rights))` or for illustrated `digest({declaration, parentRightsDeclarationId, mediaDigest})`; mediaDigest = sha256 of manifest JSON or `digest([])`. Stored on revision, submission and batch (`author-submissions.js:351-360`).
- `loadSubmittedPackage(account, submissionId, session)` (`author-submitted-package.js:36-156`) is AUTHOR-scoped (`authorAccountId: account._id` :39, `ownStory` :44, revision author filter :48) and recomputes/validates every digest (:137-154); returns {submission, revision, rights, parent, manifest, document}. `submittedPackage` (:158-185) shapes {submission, story:{id,title}, revision:{id,number,formatVersion}, packageDigest, rights, media, chapter:{id,document}|metadata}. `submittedImage` (:187+) is also author-scoped. A moderator/AI worker needs a non-owner variant (extract the integrity core). Revision `packageDigest` is a ready fingerprint anchor for input hashing.

## 3. Similarity source eligibility
- Chapter (`models/content/chapter.model.js`): status `draft, submitted, approved, scheduled, due, published, unpublished, archived, cancelled` (:3-13); draftRevisionId/currentRevisionId/publishedRevisionId (:42-44); firstReleasedAt/publishedAt (:48-49); cancelledAt + cancellationReason `author-role-removed|account-deleted` (:14,50-51); index {storyId,publishedRevisionId,orderKey} (:58). Chapter has NO authorAccountId: author = `Story.authorAccountId` (`story.model.js:23`), or `ContentRevision.authorAccountId` (`content-revision.model.js:24`), or `PublicationSubmission.authorAccountId` (:16).
- Story: publicationStatus `draft, submitted, under-review, approved, published, unpublished, archived` (`story.model.js:2-10`); publishedRevisionId (:50); authoringFrozen (:52).
- Published chapter = `Chapter.status==="published"` with `publishedRevisionId` (unpublished chapters keep publishedRevisionId and firstReleasedAt, so status must be checked). Pending chapter = a `PublicationSubmission` with chapterId and status in `validated|pending-review|decision-pending` (same set as `author-story-lifecycle.js:31-33`; cancel paths also include `approved`: `admin-close-author-account.js:103`, `revocation.js:153`) on its `revisionId`. Whether approved-not-yet-published counts as pending is a plan decision.
- Cancelled/deleted marking: account deletion sets chapter `status=cancelled, cancelledAt, cancellationReason=account-deleted, publicationTransition.result=account-deleted` (`admin-close-author-account.js:88-98`) and sets stories `authoringFrozen=true` and `unpublished` if published/in-review (:66-76); Author-role removal does the same with `author-role-removed` (`author-access/revocation.js:133-143,158-160`). Submissions get `status=cancelled, cancelledAt, cancellationReason`, claim cleared, `claimVersion++` (`admin-close-author-account.js:107-122`). Cancel skips submissions whose `revisionId` is in the published-revision set (:100-105), so a deleted author published chapter is hidden via Story `unpublished`, not chapter `cancelled`: eligibility must join Story.publicationStatus.
- EmbeddingArtifact carries `authorAccountId` and `eligibilityStatus` (`embedding-artifact.model.js:13-14`) but is append-only, while eligibility changes over time: re-validate top-k hits against Chapter/Story/Submission after `$vectorSearch` (own-author exclusion can be a search pre-filter on `authorAccountId`).
