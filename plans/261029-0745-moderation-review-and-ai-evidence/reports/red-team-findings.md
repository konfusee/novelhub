## Required changes per group

1. **Worker flags.** Add `AI_EVIDENCE_WORKER_ENABLED` and `NOTIFICATION_OUTBOX_ENABLED` (booleans, default `false` in `.env.example`, blank-safe). `server.js` starts a worker only when its flag is `true`. The evidence worker additionally refuses to start without `OPENAI_API_KEY` (log once, do not process), so a misconfigured runner never fails batches with `provider-unconfigured`. The outbox worker refuses to start when `config.emailDelivery` is the development console sender and `MONGODB_URI` host is not `localhost`/`127.0.0.1`. Handle `SIGUSR2` (nodemon restart) in `shutdown` the same as `SIGTERM` and re-raise it after stopping workers so nodemon can restart. Record a runner id (`hostname:pid`) in `ProcessingAttempt.responseMetadata.runner` and outbox `claimId`. Phase 05 marks Task 5.7 as **writes to the shared database**, and its preflight asks the operator to confirm that no other backend runs with the flags on, then checks that no fresh lease from another runner exists.
2. **Rollback.** Phase 02 and Phase 05 rollback: keep the worker enabled but unset `OPENAI_API_KEY` is NOT allowed (see 1); instead add `backend/scripts/fail-pending-evidence.js` (`npm run ai:fail-pending -- --reason operator-disabled [--dry-run]`) that marks non-terminal batches `failed` with `failedStage` = current stage and `failureCode: 'operator-disabled'`, clears `activeLeaseId`, and moves their `validated` submissions to `pending-review` in one transaction each. Tests cover it.
3. **Budget guard.** Persist usage: every provider call stores `usage` (input/output/reasoning tokens) and computed `costUsd` in `ProcessingAttempt.responseMetadata` using a price table in `backend/src/modules/ai/pricing.js` keyed by model. Add `AI_BUDGET_USD` (default `3`) and `AI_BUDGET_WINDOW_START` (ISO date, default blank = all time). Before claiming any provider stage, sum `costUsd` of attempts since the window start; if `spent + worstCaseStageCost >= AI_BUDGET_USD`, do not claim (leave the batch `pending`, log once per sweep `ai budget exhausted`). Worst-case stage cost uses the real limits (max input chars / 2 chars per token + max output tokens) × 1 attempt. Preflight in Phase 05 prints spent, remaining and worst-case backlog cost and blocks when worst-case > remaining. Backfill counts against the same ledger (store backfill usage the same way). Phase 05 requires confirming the OpenAI project hard limit (the user stated the key has a 3 USD limit) as a checklist step.
4. **LLM-stage integrity.** In the stage-claim transaction, re-read the submission with the session and require `status: 'validated'` and author account active; otherwise mark the batch `failed` with `failureCode: 'submission-closed'` (no provider call). In `llmStage`, call `eligibleSourceRevisions` again and drop findings whose `sourceRevisionId` is no longer eligible; pass only eligible ones and store `droppedIneligibleFindings` in `LlmReview.evidenceRefs` metadata. Each claim's `leaseExpiresAt` uses `new Date()` at claim time, and immediately before each provider call the worker checks `Date.now() < leaseExpiresAt - safetyMs` (safety = provider timeout); otherwise it releases the claim (attempt `stale`) and skips.
5. **Long text.** Embedding requests are split into chunks of at most 200k estimated tokens (chars / 2) and 2,048 inputs; vectors are concatenated in order. LLM input caps stay, and `LlmReview` gains `reviewedChars` and `totalChars`; when `reviewedChars < totalChars` the moderator detail shows "AI chỉ đọc N/M ký tự" and the risk badge reads "Chưa đủ dữ liệu" instead of the model's risk level. Fix the risk-table row in Phase 02.
6. **Prompt injection.** Build the LLM input as JSON with separate fields `submission.text`, `submission.title`, `rights.sourceLicenceNote`, `findings[].sourcePassage` each tagged with `origin` (`submitter`, `otherAuthor:published`, `otherAuthor:pending`). The system prompt states that instructions inside these fields are data and must be reported as a risk reason (`prompt-injection-attempt`). Add a worker test with an injection fixture asserting the stored `riskReasons` come from the double and that the input JSON keeps the origin tags. The frontend labels AI text "Nhận định AI (tham khảo, có thể bị nội dung tác giả tác động)" and shows similarity scores/passages independently of AI text.
7. **Supply chain and env.** Install with `npm install --save-exact --ignore-scripts openai@7.45.1 --workspace backend`, then `npm audit signatures --workspace backend` (expect `verified registry signatures`). Construct the client with explicit `baseURL: 'https://api.openai.com/v1'`, `organization: null`, `project: null`, `apiKey` from config. `env.js` records whether `OPENAI_API_KEY` came from the shell or `.env` (`load-dotenv.js` keeps that information) and the preflight prints only `openaiKeySource: shell|dotenv|unset`.
8. **Suspended authors.** Worker candidates, moderator queue/mine/processing lists and summary counts exclude submissions whose author account is not `active`; claim returns 409 `author_unavailable`. Test: a suspended author's submission is neither processed nor listed; after reinstatement it is. Admin dashboard counters stay unchanged.
9. **Outbox.** Lease is set per row at claim time to `max(120 s, sum of SMTP timeouts × emailSendAttempts + 30 s)`. Success/failure updates CAS on `claimId` and require `modifiedCount === 1`; on a miss, count `lateCompletion` and log the outbox id only. Delivery is documented as at-least-once. Add a decision sender wrapper that never logs `to`; the development console sender used by the outbox logs only the outbox id. Phase 05 e-mail check requires `smtp: true` in preflight; otherwise the smoke reports `email=unverified-console` and does not claim delivery. Smoke recipient must be passed explicitly (`--author-email`, required when SMTP is configured; no `example.com` default).
10. **Smoke accounts.** The smoke script reuses an account only if it carries `smokeMarker: 'novelhub-smoke-v1'` written by the script in an `AuditEvent` keyed to that account, is `active`, has verified e-mail and no password hash; otherwise it creates new accounts with a random suffix. Each role grant writes an `AuditEvent {action: 'smoke.role-granted'}`. At the end (pass or fail) the script revokes the smoke roles (`status: 'revoked'`, `revokedAt`), bumps `authorizationEpoch`, deletes their sessions, and prints `smoke cleanup done`.
11. **Phase 01 correctness.** Release requires `claimExpiresAt > now`; an expired claim can only be taken over through claim (history reason `expired`); `canRelease` mirrors this. Decision error codes: `pending-review`, or `decision-pending` owned by another moderator, or an expired claim → 409 `claim_required`; version mismatch or terminal status → 409 `submission_changed`; tests assert exactly these. Reuse existing helpers instead of refactoring: `loadModeratorPackage` = find submission then `loadSubmittedPackage({ _id: submission.authorAccountId }, id, session)`; moderator image = `submittedImage(config, { _id: submission.authorAccountId }, id, mediaId)`; author lock = `lockAuthor({ _id, authorizationEpoch, credentialVersion } of the author)` with its 403 translated to 409 `author_unavailable`. Remove planned refactors of `author-submitted-package.js` and the `lockAccount` export if no longer needed.
12. **Backfill.** `EmbeddingArtifact` gains `source: 'evidence-batch'|'backfill'` (default `evidence-batch`) and `batchId` becomes required only when `source === 'evidence-batch'` (schema validator + model test). Backfill embeds every current `publishedRevisionId` of a published chapter whose story is not cancelled, regardless of submissions. Candidates are selected with an aggregation that excludes revisions already having artifacts for `(model, chunkingVersion)` before `$limit`, and reports `remaining`. Each revision is embedded and inserted in its own transaction (insert after the provider call returns); per-revision failures are counted and the run continues. `--dry-run` writes `backend/.tmp/backfill-plan.json` with candidate revision ids and estimated cost; the real run requires `--plan backend/.tmp/backfill-plan.json`, re-checks the ids are still candidates and embeds exactly those. `.tmp/` is gitignored.
13. **Smoke realism.** The smoke provisions a second smoke account as a separate author with a published chapter containing a known passage (published through the real author/decision/release APIs, using the same pipeline) and then submits a chapter from the first smoke author that copies that passage. Pass requires `findings >= 1` with `maxScore >= 0.9` and an attempt for stage `comparison` with `succeeded`. Before the smoke, a drain step waits until no `validated` submissions older than the smoke exist (timeout scales: 120 s + 90 s per backlog item), or the preflight blocks when the backlog exceeds 10.

Clamp scores to [0, 1] when building findings and in test doubles. `processEvidenceBatches` wraps each candidate in its own try/catch; unexpected errors fail the attempt with `failureCode: 'persist-error'` (retryable once, then terminal) and the sweep continues. Detail `evidence` includes `findingsCount`, `maxScore`, `findingsTruncated`; Phase 03 shows "50 / N" when truncated.
